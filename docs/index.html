Technical Architecture

Key architectural differences for local desktop automation.

Native Swift vs. Catalyst WebKit

The official Home Assistant companion app runs an iOS build via Mac Catalyst, keeping a WebKit browser engine and helper processes active in the background (using 250 MB to 650 MB of RAM). StateBeacon contains no web views. Written in native Swift with AppKit and Darwin APIs, it runs as an accessory daemon using roughly 30 MB of RAM.

Direct MQTT Socket vs. HTTP Webhooks

Rather than routing periodic HTTP webhooks through cloud proxies, StateBeacon maintains a local TCP/TLS socket to your broker with Last Will and Testament (LWT) for instant offline detection. It follows standard Home Assistant Discovery format (homeassistant/<domain>/...), matching the entity conventions used by Windows HASS.Agent.

Kernel Event Watchers vs. Timer Polling

Rather than polling on a timer, StateBeacon listens to kernel file descriptor events (via DispatchSourceFileSystemObject) on the macOS Assertions.json database. Focus mode and Do Not Disturb transitions reach Home Assistant in under 50 milliseconds.

Installation

Setup in three steps.

1

Install App

Download StateBeacon.dmg, open the disk image, and drag StateBeacon into your Applications folder.

2

Configure Broker

Click the antenna icon in the menu bar, open Preferences, and enter your MQTT broker IP and credentials.

3

Automatic Discovery

Your Mac appears in Home Assistant under Settings → Devices & Services → MQTT.
